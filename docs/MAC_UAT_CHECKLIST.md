# پذیرش یکپارچه مالی دیدار روی مک — یک دور کامل

وضعیت فعلی: **MAC_UAT_PENDING / REAL_RFID_PENDING**. آزمون لینوکس Codex جای اجرای انسانی روی مک، ترازو یا خواندن واقعی RF نیست. نگاشت API واقعی ته‌حساب **BLOCKED_BY_SPEC** است؛ تنها قالب مستقل دیدار و شبیه‌ساز آزمایش می‌شوند. حسابداری قانونی، مالیات، مالکیت و مجوز کیف پول نیازمند تأیید حرفه‌ای هستند. هیچ پرداخت، خرید طلا، برداشت یا ثبت آنلاین واقعی مجاز نیست.

## آماده‌سازی با حفظ اطلاعات

پیش‌نیازها همان Gate 0 تکمیل‌شده‌اند: Node 24، Bun 1.4.3، Docker Desktop و مرورگر Chromium نصب‌شده Playwright. اطلاعات مک و نسخه کد را ثبت کنید. تغییرات محلی خود را پاک نکنید.

```bash
git status --short
git switch main
git pull --ff-only origin main
git rev-parse HEAD
bun run local:setup
bun run local:browser
bun run local:test
bun run local:dev
```

آزمون خودکار از پایگاه موقت مستقل استفاده می‌کند؛ داده UAT پایدار را حذف نمی‌کند. `local:setup` مهاجرت‌های افزایشی را اجرا می‌کند. برای توقف فقط `bun run local:stop` یا Ctrl+C استفاده شود. هرگز `down -v`، پاک‌سازی volume، reset اجباری Git یا حذف پایگاه برای رفع اختلاف اجرا نکنید. روی مک `CHROMIUM_PATH` را تعیین نکنید مگر مرورگر خاصی دارید؛ مسیر لینوکسی `/usr/bin/chromium` فقط override محیط Cloud است.

در ترمینال دوم، پس از آماده‌شدن API:

```bash
bun run uat:prepare
```

این فرمان فقط API روی loopback و ورود نمونه محلی را می‌پذیرد. یک تأمین‌کننده، مشتری و دو محصول جدید **ساختگی و منتشرنشده** می‌سازد؛ ۲۰ UID/EPC تازه در یک پذیرش و قرارداد ترکیبی ۵۰٪ طلا/۵۰٪ ریال آماده می‌کند. وزن‌ها ورودی صریح QA هستند، نه ادعای اندازه‌گیری فیزیکی. پرداخت/خرید/تسویه اجرا نمی‌کند. شناسه‌ها و ایمیل‌ها در `.local/financial-uat.json` و خروجی ترمینال هستند. اجرای دوباره موفق، همان داده تجاری را نگه می‌دارد. فایل `.local` را وارد Git نکنید. در صورت قطع وسط آماده‌سازی، داده ناقص ساختگی را نگه دارید و خطا را گزارش کنید؛ پایگاه را پاک نکنید.

مدیر: `admin@didar.test` با رمز نمونه `DidarDemo2026!`. ایمیل مشتری و تأمین‌کننده در خروجی آماده‌سازی است؛ رمز **فقط نمونه محلی** آن‌ها `DidarUATFinancial2026!` است. این اطلاعات برای محیط واقعی نیستند. از عکس‌گرفتن رمزها و توکن‌ها خودداری کنید. پنل دیدار در `http://localhost:3000` است؛ اعتبارنامه بومی Mercur جداست.

## سناریوی واحد

1. **پذیرش و قطعات:** در `/manage/operations` پذیرش دارای شماره `DIDAR-UAT-…` را باز کنید. ردیف‌ها باید ۵ قطعه/۱۳۵٫۰۰۰ گرم، ۲/۱۲۷٫۰۰۰، ۱۲/۱۱۷٫۰۰۰ و ردیف جداگانه ۱/۱۰۰٫۰۰۰ گرم داشته باشند؛ ۲۰ UID مستقل. وزن‌های ردیف اول ۲۵،۲۶،۲۷،۲۸،۲۹ گرم؛ دوم ۶۳،۶۴؛ سوم ۹،۹٫۱،۹٫۲،۹٫۳،۹٫۴،۹٫۵،۱۰،۱۰٫۱،۱۰٫۲،۱۰٫۳،۱۰٫۴،۱۰٫۵ گرم است. عیار ۷۵۰ و اجرت ۱۲٪. وزن تاریخی/UID/EPC را بازنویسی نکنید.
2. **تطبیق و مجوز:** پذیرش ثبت‌شده تغییرناپذیر است. در یک پیش‌نویس ساختگی جدا، عدم تطابق وزن/تعداد باید جلوی تأیید را بگیرد. ورود تأمین‌کننده در مرورگر خصوصی باید فقط همین تأمین‌کننده و قطعاتش را نشان دهد؛ تأیید پذیرش/خرید/تسویه برای او مجاز نیست. مجوزهای عملیاتی Phase 1 پیش‌فرض خاموش‌اند؛ تغییر موقت را پس از آزمون برگردانید.
3. **RFID:** جلسه شمارش همین تأمین‌کننده بسازید. پنج EPC از اتصال‌های آماده‌شده را با حالت شبیه‌ساز یا تایپ/Enter وارد کنید؛ تعداد متمایز ۵، غایب ۱۵. تکرار یکی تعداد را بیشتر نکند. UID همان قطعه نیز خوانش تکراری است. شناسه ناشناخته علامت بخورد و موجودی را تغییر ندهد. HID واقعی، RF و برنامه‌ریزی تراشه فقط با سخت‌افزار واقعی قابل تأییدند.
4. **انتشار:** در `/manage` دو محصول QA را پیدا و منتشر کنید. تصویر خالی به معنی نبود عکس واقعی است؛ عکس تولیدشده یا سابقه محصول اصلی تغییر داده نمی‌شود. تأمین‌کننده اجازه انتشار master ندارد.
5. **نرخ و قرارداد:** فقط در پایگاه ساختگی نرخ ۶۵٬۰۰۰٬۰۰۰ ریال/گرم۷۵۰، توزیع۳٪، خرده‌فروشی۷٪ و VAT۱۰٪ روی اجرت/توزیع/خرده‌فروشی را بررسی کنید. `/manage/finance` قرارداد تأییدشده MIXED۵۰٪، امانی، سررسید۷روز را نشان دهد. پیش از پرداخت مشتری، پذیرش امانی بدهی خرید ایجاد نکرده باشد.
6. **فروش نمونه ۱۰۰ گرم:** به حساب مشتری QA وارد شوید، محصول جداگانه۱۰۰گرمی را بخرید. قیمت باید طلای پایه۶٬۵۰۰٬۰۰۰٬۰۰۰ + اجرت۷۸۰٬۰۰۰٬۰۰۰ + توزیع۱۹۵٬۰۰۰٬۰۰۰ + خرده‌فروشی۴۵۵٬۰۰۰٬۰۰۰ + VAT۱۴۳٬۰۰۰٬۰۰۰ = **۸٬۰۷۳٬۰۰۰٬۰۰۰ ریال** باشد؛ معادل نظری۱۲۴٫۲گرم۷۵۰. پرداخت را فقط با دکمه آزمایشی موفق کنید.
7. **همان UID و بازپخش:** سفارش باید همان UID رزروشده را فروخته نشان دهد. تازه‌سازی و تکرار callback آزمایشی، فروش/تعهد/درخواست را تکرار نکند. در آزمون مستقل قطعه دیگری، شکست/لغو/انقضا همان UID را آزاد کند. دو مرورگر برای یک UID نباید هر دو موفق شوند.
8. **تعهد مستقل از حاشیه فروش:** مدیر و تأمین‌کننده در `/manage/finance` اصل حق قراردادی **۱۱۲گرم۷۵۰ =۸۴٬۰۰۰٬۰۰۰میکروگرم طلای خالص** را بررسی کنند. سهم قرارداد ترکیبی: **۴۲٬۰۰۰٬۰۰۰µg خالص =۵۶گرم۷۵۰** به‌علاوه **۳٬۶۴۰٬۰۰۰٬۰۰۰ریال**. اجرت با حاشیه/مالیات مشتری اشتباه نشود. نسخه قرارداد و نرخ سفارش محفوظ باشند؛ نسخه جدید با تاریخ آینده یا تغییر بعدی، سفارش قبلی را تغییر ندهد.
9. **درخواست خرید، نه خرید اجراشده:** `/manage/treasury` یک درخواست طلا برای همان فروش داشته باشد. پیش از ثبت خرید، وضعیت آن «خریدشده» نباشد. مدیر درخواست را با دلیل تأیید کند.
10. **خرید ساختگی:** در خزانه یک خرید دستی با طرف معامله و سند QA، وزن۶۰٬۰۰۰میلی‌گرم، عیار۹۹۵، نرخ۶۵٬۰۰۰٬۰۰۰، هزینه۵٬۱۷۴٬۰۰۰٬۰۰۰ریال، محل نگهداری ساختگی و تأیید مالکیت مستند ثبت و سپس تأیید کنید. مقدار خالص **۵۹٬۷۰۰٬۰۰۰µg** است. هیچ درخواستی به بانک یا بازار ارسال نشود.
11. **تخصیص و کنترل مقدار:** از خرید،۴۲٬۰۰۰٬۰۰۰µg به درخواست تخصیص دهید. بیش از خرید یا حق درخواست باید رد شود. تخصیص به‌تنهایی تعهد را صفر و کالا را تحویل‌شده نکند. در آزمون خودکار چند خرید/چند درخواست و رقابت همزمان نیز پوشش داده می‌شود.
12. **مالکیت و تصرف مستقل:** پیش از ثبت سند انتقال مالکیت و سپس تحویل/نگهداری برای تأمین‌کننده، تسویه طلا باید رد شود. این دو سند مستقل QA را ثبت کنید؛ برای حالت نگهداری نزد دیدار، «نگهداری امانی برای تأمین‌کننده» را انتخاب کنید. انتقال سند به‌تنهایی اثبات دریافت فیزیکی نیست.
13. **تسویه جزئی و ترکیبی:** ابتدا۲۰٬۰۰۰٬۰۰۰ و سپس۲۲٬۰۰۰٬۰۰۰µg طلا تسویه آزمایشی کنید. مانده طلا باید صفر شود. ریال را جدا با سند QA تسویه کنید، یا طبق مرحله۱۴ بخشی را به کیف پول منتقل کنید. درخواست تنها وقتی مانده طلای **و** ریال آن صفر است، تسویه‌شده باشد. خرید همچنان تاریخچه، مالکیت و نگهداری مستقل داشته باشد.
14. **کیف پول و دفتر:** در `/manage/ledger` می‌توانید۱٬۰۰۰ریال از تعهد همان تأمین‌کننده را به کیف پولش منتقل کنید؛ در این حالت فقط۳٬۶۳۹٬۹۹۹٬۰۰۰ریال تسویه ریالی باقی است. انتقال، بدهی دوم ایجاد نمی‌کند. `/account/wallet` باید۱٬۰۰۰ریال آزاد نشان دهد. برای مشتری، مدیر یک واریز **ساختگی** با سند و سپس آزادسازی ثبت کند؛ رزرو/وثیقه خرج‌کردنی نیستند، انتقال بیش از آزاد رد شود، برداشت خارجی وجود نداشته باشد. سندها به‌ازای ریال، مقدار طلا و یادداشت امانی مستقل تراز باشند؛ تعداد نامتوازن صفر.
15. **اسناد تجمیعی شبیه‌ساز:** `/manage/tahesab` نگاشت QA آماده‌شده و مرجع فاکتور را نشان دهد. دوره گذشته/تا زمان حال را ببندید. JSON مدیر نباید مشتری، نشانی، UID/EPC یا سفارش خریدار داشته باشد. دریافت کالا، تعهد فروش، سهم خرید ثبت‌شده، تخصیص، انتقال و تسویه با نوع جدا باقی بمانند. پاسخ «خطای موقت» و سپس «موفق» را آزمایش کنید؛ Factor_Code و شماره سند شبیه‌ساز ثابت، ثبت تکراری ایجاد نشود. تطبیق دوباره همان نتیجه را بدهد. آزمون خودکار ویرایش/حذف سند خارجی شبیه‌ساز را نیز تشخیص می‌دهد. عبارت BLOCKED_BY_SPEC باید همچنان دیده شود؛ این تأیید API واقعی نیست.
16. **مرجوعی و بازیافت حق:** مشتری برای همان UID درخواست مرجوعی کند؛ مدیر دریافت فیزیکی و سپس استرداد **مالی آزمایشی** را مستقل ثبت کند. دریافت قطعه به‌تنهایی ادعای بازپرداخت بانکی نیست. اگر قبلاً تسویه شده، مانده منفی تأمین‌کننده «مطالبه/پیش‌پرداخت قابل بازیافت» است؛ سند قبلی حذف نشود و طلا/وجه برگشته فرض نشود. پس از بازرسی، restock یک‌بار قطعه را آزاد کند؛ دوباره‌زدن موجودی را زیاد نکند. دوره جدید، برگشت و یادداشت دریافت فیزیکی را مستقل صادر کند.
17. **پایداری و گزارش نهایی:** `/manage/acceptance` کنترل‌های تطبیق را تازه کنید؛ اختلاف موجودی، سند نامتوازن، مانده منفی غیرمجاز کیف پول، تخصیص بیش از خرید، فروش فاقد سند و منبع تکراری خروجی همه صفر باشند. موارد موجودی متعلق به دیدار بدون سند بهای قدیمی صادقانه «نیازمند مستندات» بماند. SHA را از ترمینال وارد و گزارش تغییرناپذیر ثبت کنید. سرورها را متوقف و دوباره `local:dev` اجرا کنید؛ UIDها، EPCها، سفارش، قرارداد، اسناد، کیف پول و شبیه‌ساز باید همان باشند. پایگاه/volume را حذف نکنید.

## ثبت نتیجه

یک بار این سناریو را کامل اجرا کنید و SHA، مدل/معماری مک، نسخه ابزارها، مرحله، مقدار مورد انتظار/واقعی و عکس بدون رمز/توکن را ثبت کنید. وضعیت‌ها را جدا گزارش کنید: نتیجه خودکار، نتیجه انسانی مک، RFID واقعی، تأیید حسابدار و نگاشت واقعی ته‌حساب. هیچ‌کدام با موفقیت شبیه‌ساز به‌طور خودکار تأیید نمی‌شوند. برای تکمیل نگاشت واقعی، فایل خصوصی OpenAPI باید به Codex داده شود؛ آن را بدون اجازه در GitHub عمومی قرار ندهید.
