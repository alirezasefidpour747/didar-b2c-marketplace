## One selected, implemented P1 correction

**CORE-23-01 / NATIVE01:** parent-only generic native Product protection was bypassable because pinned Mercur/Medusa workflows mutate actual child IDs independently. Independent baseline real HTTP showed ordinary linked-parent variant DELETE = 409, but the same DIDAR Variant under an unrelated native parent DELETE = 200 with PostgreSQL soft-deletion. A separate batch also deleted a linked Variant. Canonical Product/Offer/UID/order/finance counts remained unchanged; this is confirmed derived Product integrity harm, not a claim of lost canonical gold.

The correction guards the reviewed concrete Product-family and standalone Option/Value targets before any native workflow: URL/body Variant IDs (including pinned `body.id` override), nested Product batches, Image/Variant associations, inventory-link Variant IDs and shared Options' many Product owners. It resolves native ownership through installed native Query; only the original `didar_product.native_id` decides whether a target is a governed DIDAR projection. Query failures propagate, GET/HEAD/OPTIONS stay untouched, explicit pages/chunks avoid default-list omissions, and mixed mutations reject before partial work. Native auth/ACL and unrelated native CRUD remain native. Internal projection workflows continue using supported native APIs.

Code: `packages/api/src/didar/native-product-guard.ts`, `native-product-targets.ts`, `src/api/middlewares.ts`; persistent regressions: `tests/native-product-targets.test.ts`, included in existing test command. No migration is applicable because no schema, stored identity or financial semantics changed. Existing accepted migration/restore evidence is inherited; no destructive reset or meaningless empty migration was added.

Independent reviewer caught two real pre-acceptance issues: the initial collector omitted the native update's optional body-ID target; the initial test fixtures assumed a fixed Product ID and auto-created native Variant. Both were corrected before candidate A verification. Two separate earlier baseline fixture runs returned legitimate native 400s; their exit-one/cleanup receipts are preserved and not called application defects or successful proofs.
