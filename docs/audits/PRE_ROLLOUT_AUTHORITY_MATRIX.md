## Product projection consistency — open architecture gap and bounded defect

The phrase “writes both records” in the recovery mapping describes an orchestration, **not one atomic transaction**. At the inspected baseline:

1. [`catalog.ts saveProduct`](../../packages/api/src/didar/catalog.ts) locks the canonical master and taxonomy tree on a `pg` client. It invokes the native create/update workflow, whose own transaction completes before the DIDAR SQL save.
2. DIDAR then writes its canonical record, slug, classification/collection relationships and audit. A caught error inside `saveProduct` attempts a native compensation (update old projection/delete newly created projection).
3. [`db.ts transaction`](../../packages/api/src/didar/db.ts) commits the caller's `pg` transaction only after `saveProduct` has returned. A deferred constraint/connection failure at this final commit is outside that compensation catch.

| Failure point | Current consequence | Evidence class |
| --- | --- | --- |
| Native workflow fails before result | DIDAR transaction rolls back; native workflow owns its internal compensation | Source review; native workflow failure completeness not independently fault-tested here |
| Native succeeds, canonical SQL throws, process remains alive | Best-effort native revert/delete runs; failure logs reconciliation required | Independently executed isolated catch-path reproduction below |
| Process dies after native commit but before canonical commit | Updated native projection or orphan native product may survive while DIDAR changes roll back | Source-supported crash window, **not** an executed kill/restart experiment |
| DIDAR final `COMMIT` fails after `saveProduct` returns | Native projection may retain new state; local compensation is no longer in scope | Source-supported transaction boundary, not independent real deferred-constraint injection |
| Compensation itself fails | Log only; no durable work item, retry/reconciliation protocol found | Source review; no automatic recovery claim |

**Bounded reproducible defect PRC-01:** compensation computes restored native publication as `old.active && old.published`, while the forward projection requires `active && published && approved`. An original active/published/unapproved canonical record is mirrored to native draft on forward write but to native published after a caught canonical failure. This is a concrete predicate correction within existing semantics, separate from a durability redesign. The coordinator may fix it after independent review; the pre-fix finding must remain in the audit trail.

## Retailer A selling Supplier B inventory — decision gate

**Current behavior:** A shop's `didar_storefront.supplier_id` must equal each selected `didar_offer.supplier_id`. `assertOfferScope` is used by quote and checkout; exact inventory also binds item/Offer/product/supplier in database guards. Orders freeze storefront origin separately from line supplier, but those separate fields are **not** sufficient legal/economic machinery for A→B resale. Current supplier contract, exposure, procurement request and settlement use the original order-line supplier. No current A retailer payable/reward/receivable or authorized B→A title transfer is implied.

**Allowed existing policy:** DIDAR Admin may operate an approved same-supplier merchant storefront without any merchant Vendor login, audit the real actor/target, and delegate existing capabilities later on the same IDs. This is ADR-BIZ-01; it is not a cross-supplier authorization.
